# Исследование «подкрутки» матчмейкинга Dota 2

Проверка народной легенды о том, что матчмейкинг Dota 2 искусственно подтягивает
винрейт игрока к 50%. Исследование построено на открытых данных
[OpenDota](https://docs.opendota.com/) и полностью воспроизводимо.

Главная методологическая идея: 50% винрейта — это **равновесие любой рейтинговой
системы**, а не доказательство вмешательства. Поэтому проект не измеряет винрейт,
а проверяет, отличается ли наблюдаемый матчмейкинг от **честного подбора по
рейтингу**, для чего строится симулятор честной системы и все статистики
сравниваются с ним.

Гипотезы, тесты и пороги зафиксированы в [PREREGISTRATION.md](PREREGISTRATION.md)
и [THEORIES.md](THEORIES.md)
до сбора данных. Итоги — в [reports/report.md](reports/report.md).

## Установка

```bash
pip install -r requirements.txt
```

API-ключ не требуется: всё работает на free tier. Если ключ есть, он подхватится
из переменной окружения `OPENDOTA_API_KEY` и снимет ограничение по объёму.

## Запуск

Этапы независимы и возобновляемы — выгрузку можно прерывать и продолжать,
кэш HTTP-ответов лежит в `data/http_cache.sqlite`.

```bash
python -m scripts.run_controls          # позитивные контроли на публичных матчах
python -m scripts.harvest_seeds         # сбор account_id
python -m scripts.crawl_players         # выгрузка историй игроков
python -m scripts.crawl_rosters         # выгрузка составов
python -m scripts.detect_cohorts        # смурфы, слабые игроки, «жители рейтинга»
python -m scripts.run_simulation        # честный матчмейкинг как нулевая модель
python -m scripts.run_negative_control  # проверка чувствительности самих тестов
python -m scripts.run_tests_ab          # тесты A и B
python -m scripts.analyse_streaks       # вопрос «выиграл N — шанс следующей?»
python -m scripts.run_tests_cd          # тесты C и D
python -m scripts.analyse_queues        # win queue / lose queue
python -m scripts.scan_dependencies     # какие зависимости вообще есть
python -m scripts.watch_bracket         # слабые и сильные в полосе 4600–5000
python -m scripts.run_theories          # остальные теории матчмейкинга
python -m scripts.build_report          # сборка отчёта
```

Тесты оценщиков (проверяют статистики на данных с известным ответом):

```bash
python -m pytest tests/ -q
```

## Как устроена проверка

Три уровня контроля, без которых вывод об отсутствии эффекта не имел бы силы:

1. **Позитивные контроли** — конвейер обязан воспроизводить заведомо
   существующие эффекты (перевес Radiant, различия винрейтов героев).
2. **Нулевая модель** — честная рейтинговая система сама даёт и сходимость к
   50%, и зависимость исхода от серии, поэтому наблюдения сравниваются с ней, а
   не с нулём. Её единственный свободный параметр калибруется по данным.
3. **Негативный контроль** — в симулятор внедряется подкрутка известной силы, и
   проверяется, что тесты её находят.

## Ограничения данных

Ограничения, найденные при разведке API, определяют весь дизайн:

- В `public_matches` нет `account_id`, а таблицы `matches`/`player_matches` в SQL-эксплорере
  содержат сейчас лишь сотни матчей в месяц. Per-player анализ возможен только через REST.
- `average_rank` заполнен почти всегда у матчей 2023 года и позже и почти никогда у
  более старых. Окно исследования ограничено этим периодом.
- Примерно у половины игроков `account_id` скрыт настройками приватности, что
  ограничивает анализ составов и требует проверки на смещение.
